# Контракт базы знаний, версия 1

Статус: техническая спецификация для реализации. Основание — P-003, P-011, P-015, P-016, P-020, P-027, P-037 и P-040 из [продуктовых решений](../product-decisions.md). Загрузчик и валидатор ещё не реализованы.

## Назначение

Вуз готовит сведения под этот контракт. Приложение принимает подготовленный пакет фактов, проверяет его и строит локальный поисковый индекс. Импорт произвольных PDF, Word, сканов, сайтов и таблиц в поставку не входит. Если исходники имеют эти форматы, их предварительно преобразует поставщик базы. Автоматический сбор данных из интернета не выполняется.

База общая для всех студентов. Каждая опубликованная запись может отображаться посетителю без идентификации. Индивидуальные права доступа и поиск по учётной записи студента не поддерживаются. Утверждение содержания и пригодности для такого показа — ответственность поставщика базы. Документ не вводит новую функцию персонального доступа.

## Формат пакета

ZIP с двумя UTF-8 файлами непосредственно в корне:

```text
dean-kb.zip
├── manifest.json
└── documents.jsonl
```

В архив не включаются исполняемые файлы, модели, поисковые индексы, пароли и инструкции для модели. Внешние URL не загружаются приложением. Индекс создаётся самим приложением, поэтому изменение embeddings не требует перекодировать исходные сведения вручную.

### manifest.json

```json
{
  "schema_version": "1.0",
  "kb_id": "university-dean-office",
  "release_id": "2026-10-20.1",
  "title": "База знаний деканата",
  "language": "ru",
  "prepared_by": "Ответственный сотрудник деканата",
  "prepared_at": "2026-10-20T10:00:00+03:00",
  "documents_file": "documents.jsonl"
}
```

| Поле | Правило |
| --- | --- |
| `schema_version` | Строго `1.0`. Неизвестная версия отклоняется. |
| `kb_id` | Постоянный идентификатор базы, 1–80 символов `a-z`, `0-9`, `-`, `_`. |
| `release_id` | Уникальное имя выпуска, 1–80 символов `a-z`, `A-Z`, `0-9`, `.`, `-`, `_`. Не задаёт приоритет фактов. |
| `title` | Непустое название, до 200 символов. |
| `language` | Строго `ru`. |
| `prepared_by` | Ответственный за подготовку пакета, непустая строка до 200 символов. Не является учётной записью приложения. |
| `prepared_at` | RFC 3339 с часовым поясом; дата подготовки, не дата вступления правил в силу. |
| `documents_file` | Строго `documents.jsonl`. |

Все поля обязательны; неизвестные поля отклоняются, чтобы опечатка не превращалась в молча проигнорированное требование.

### documents.jsonl

Одна JSON-запись на строку, одна запись описывает один источник. Ниже запись показана с переносами только для чтения; в пакете она занимает одну строку.

```json
{
  "id": "certificate-policy",
  "title": "Порядок получения справок",
  "source_label": "Памятка деканата, утверждённая редакция",
  "source_url": null,
  "sections": [
    {
      "id": "request",
      "title": "Как заказать справку об обучении",
      "text": "Для получения справки об обучении обратитесь в деканат. При обращении укажите ФИО и номер группы.",
      "locator": "Раздел 1",
      "search_phrases": ["Как получить справку об обучении?", "Где заказать справку?"]
    },
    {
      "id": "processing-time",
      "title": "Срок изготовления справки об обучении",
      "text": "Справка об обучении изготавливается в течение трёх рабочих дней после обращения в деканат.",
      "locator": "Раздел 2",
      "search_phrases": ["Сколько делают справку об обучении?"]
    }
  ]
}
```

**Пример вымышленный, не является фактом о конкретном вузе.** Тестовые записи не включаются в рабочую базу незаметно для сотрудника.

| Поле документа | Правило |
| --- | --- |
| `id` | Уникальный в пакете, формат идентификатора как у `kb_id`. Сохраняется при исправлении того же источника. |
| `title` | Непустое название, до 300 символов. |
| `source_label` | Непустое описание происхождения: название положения/приказа/памятки, при наличии номер, дата и редакция; до 1000 символов. |
| `source_url` | `null` либо HTTPS-ссылка для справки; до 2048 символов. Приложение не скачивает содержимое ссылки и не открывает внешний браузер студенту. |
| `sections` | Непустой массив смысловых фрагментов. |

| Поле фрагмента | Правило |
| --- | --- |
| `id` | Уникальный в документе, формат идентификатора как у `kb_id`. |
| `title` | Непустая тема фрагмента, до 300 символов. |
| `text` | Самодостаточный русский текст фактов, 1–8000 символов. Без HTML, скриптов и команд. |
| `locator` | Непустая ссылка на место в исходнике: пункт, раздел, страница либо имя утверждённой записи; до 300 символов. |
| `search_phrases` | Массив из 0–20 вариантов вопросов, каждый до 300 символов. Помогает поиску; сами вопросы не являются источником фактов. |

Все перечисленные поля обязательны, включая `null` и пустой массив там, где они разрешены. Неизвестные поля отклоняются. Идентификатор цитируемого фрагмента: `document_id/section_id`.

## Правила подготовки содержания

1. Разделять разные темы, но не отрывать условие или исключение от правила. В тексте «срок — три дня» явно указывать, какой услуги он касается и рабочие ли это дни.
2. Не рассчитывать на знания модели о местных правилах. Если нужны кабинет, контакты, часы работы, перечень документов или срок — включить их явно.
3. Вместо относительных формулировок «завтра», «в этом году» указывать даты и периоды. Если правило действует ограниченное время, описать этот период в самом фрагменте.
4. Публиковать одну согласованную текущую редакцию сведений. Историю документов не загружать как набор равноправных действующих правил. При выявленном противоречии помощник сообщает о расхождении, не применяет приоритеты автоматически.
5. Не включать инструкции вида «игнорируй правила приложения». Содержание базы рассматривается как данные, не как исполняемые инструкции, даже если подобный текст всё же попал в пакет.
6. Для каждого фрагмента сохранять происхождение. В «Источниках» показываются название, `source_label`, `locator` и исходный текст фрагмента. Ссылка на сайт не заменяет содержащиеся в пакете факты.
7. `prepared_at` не продлевает действие фактов автоматически. За актуальность и выпуск обновления отвечает поставщик содержания; приложение не гарантирует выявление всех смысловых ошибок или противоречий при загрузке.

## Проверка и применение

Технические начальные ограничения загрузчика: архив до 50 MiB, распакованные данные до 200 MiB, до 10 000 документов и 50 000 фрагментов. Это защитные пределы формата, не обещание производительности на таком объёме. Изменять их после замеров, явно вместе с документацией.

Проверять:

- только два ожидаемых обычных файла; без вложенных архивов, симлинков, шифрования, повторяющихся путей и выхода за каталог распаковки;
- UTF-8, корректный JSON/JSONL, отсутствие повторных JSON-ключей, обязательные поля, типы, границы размеров, идентификаторы и их уникальность;
- непустой корпус, поддерживаемые язык и версию, одинаковый `kb_id` для обновления установленной базы; смена `kb_id` — явная замена базы сотрудником;
- отсутствие NUL/недопустимых управляющих символов, безопасный вывод текста без исполнения HTML;
- успешное построение локального поискового индекса и доступность всех ссылок на фрагменты.

Ошибки возвращать с путём поля, номером строки JSONL и понятной причиной. Неверный пакет не меняет действующую базу.

Обновление выполняется сотрудником по паролю **только в режиме обслуживания без активного разговора**. На время проверки и применения новые разговоры не запускаются. Сначала подготовить и проверить новую базу во временном каталоге; затем заменить рабочий указатель/каталог целиком. После сбоя должен остаться целый старый либо целый новый набор, а не смесь данных и индексов. Это обеспечение целостности обновления, а не функция хранения истории и ручного отката.

Индекс хранит `kb_id`, `release_id`, хеш исходного пакета, имя и точную ревизию embedding-модели. При несовпадении индекс перестраивается до возврата в рабочий режим. Семантический валидатор не объявляется доказательством достоверности содержания.

## Связь с ответами и журналом

Генератор получает только найденные фрагменты и контекст текущего разговора. Возвращённые идентификаторы источников должны принадлежать переданным фрагментам; неизвестные ID отклоняются. Это проверяет происхождение ссылок, но не доказывает автоматически истинность каждой переформулировки.

Для ответов из базы требуются ссылки на фрагменты. Для уточнения, отсутствия сведений или сообщения о системной ошибке пустой список допустим; для сообщения о противоречии сохраняются найденные конфликтующие источники.

Журнал на 30 дней хранит `kb_id`, `release_id`, вопрос, текст ответа и снимки использованных фрагментов с происхождением. Поэтому старый ответ можно проверить и после замены базы; хранить ради этого старую базу целиком не требуется. Журнал не участвует в контексте нового студента.
