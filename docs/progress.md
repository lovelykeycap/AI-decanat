# Ход разработки

Статус: приложение реализуется по development-plan.md. Полный продукт ещё не готов к приёмке; ниже отдельно указаны работающий код, фактические проверки и открытые зависимости.

## Уже реализовано

- Изолированное окружение Python 3.12, воспроизводимые зависимости в uv.lock, CLI для запуска/диагностики/базы/настроек.
- Воспроизводимая установка моделей по tools/model-sources.json: закреплённые ревизии и ожидаемые SHA-256, проверка до подключения, общий lock с работающим приложением.
- Строгий контракт подготовленной базы, экспорт JSON Schema, проверка ZIP/JSON/UTF-8/идентификаторов, безопасная замена базы без частично установленного индекса.
- Локальный FTS5-поиск и реализация hybrid retrieval с BGE-M3, происхождение каждого фрагмента, контекст последующих вопросов.
- Единые адаптеры Codex и Responses API, JSON Schema ответа, проверка источников, нормализация ошибок, ручной режим и opt-in fallback на API.
- Управление одной сессией: вставание в начале, завершение/посадка, контекст, отмена и защита от запоздалых ответов, таймер 60+15.
- Локальный HTTP/WebSocket-протокол для desktop, IPC bearer, пароль сотрудника Argon2, защищённые настройки, keyring, журнал на 30 дней.
- Служебная диагностика без раскрытия ключа, перечисление аудиоустройств, настройки микрофона/динамиков и смена пароля. Изменение аудиоконфигурации требует перезапуска и блокирует новые разговоры до него. Ограничение попыток входа защищено от одновременных HTTP-workers.
- whisper.cpp/Whisper small для локального ASR, Silero TTS и VAD, сегментация реплик с pre-roll.
- Собираемый C++ WebRTC APM-мост и Python duplex-аудиокомпонент с опорным сигналом динамиков; голосовая отмена подключена к контроллеру сессии.
- Unreal C++/Slate-проект: студенческий экран, формы сотрудника, IPC-клиент, управление body-анимациями и условная локальная ACE-интеграция. Скрипт создания карты и supervisor запуска.

Наличие исходников Unreal не означает, что они скомпилированы или что персонаж уже готов.

## Что ещё нельзя считать проверенным

1. Полноценный фотореалистичный персонаж не создан: нет установленных Unreal/MetaHuman, реальных character/animation-assets и локального ACE-provider. Desktop-код не компилировался. Потребуются настоящая сборка и визуальная приёмка, включая очистку очередей мимики при перебивании.
2. Целевая Windows/NVIDIA-среда отсутствует. Не проверены packaged build, синхронизация лица со звуком, акустическое перебивание, киоск ОС, восьмичасовой прогон и минимальная конфигурация оборудования.
3. Нет реальной подготовленной вузом базы. Все показанные ответы получены на вымышленных тестовых данных; фактические правила вуза не подтверждались.
4. BGE-M3 уже испытана на синтетическом корпусе; общее качество retrieval и достаточность контекста на реальном объёме базы остаются открытыми. Top-8/regex-проверки не являются доказательством фактической корректности всех возможных ответов.
5. Доступность реального API зависит от ключа/модели. Разрешённость схемы подписочного Codex для публичной эксплуатации требует отдельного подтверждения; успешный вызов CLI её не доказывает.
6. Пользователь не утвердил образец голоса и визуальный образ. Скриншот/рендер отсутствующего персонажа не подменяется макетом.
7. Консервативные границы фрагментов испытаны в логике и реальном синтезе, но DAC-тайминги, связность озвучки и слышимая остановка ещё требуют проверки на физических устройствах. Полный прерванный ответ помечается interrupted и не считается целиком услышанным.

## Следующий порядок работы

Проверки доступных локальных моделей и hybrid retrieval пройдены в указанном диагностическом объёме. Следующий обязательный этап — получить совместимый Unreal/MetaHuman/ACE-комплект и целевой GPU-стенд, собрать настоящий персонаж и desktop, проверить полный дуплекс и синхронизацию, затем выполнить всю матрицу приёмки. Кандидат стека и конкретные недостающие компоненты записаны в `docs/target-environment.md` и `assets/manifest/desktop-stack.json`. Windows выбрана по официальной матрице локального ACE, не по предпочтению ОС. Архивы NVIDIA требуют Developer login и пока не получены. Пользователь сообщил, что пока нет возможности войти в Epic Games/NVIDIA; этот этап остаётся внешней зависимостью, без подмены персонажа макетом.

Обновление подготовки стенда: пользователь предложил Windows-ноутбук с Core i5 / мобильной RTX 2050 и готов организовать аккаунты/удалённый доступ. Составлено `docs/windows-testhost-checklist.md`: RustDesk-сеанс с Mac, затем проверка управления и настройка SSH; входы Epic/NVIDIA/Codex выполняет владелец. Доступ ещё не подключён. У RTX 2050 стандартно 4 GB VRAM, поэтому пригодность для выбранной diffusion-мимики не подтверждена; экономный локальный provider и общая сцена требуют отдельного теста.

При повторном запуске Whisper с GPU по умолчанию обнаружен нативный сбой выделения Metal-буфера в ограниченной macOS-среде. Режим ASR теперь выбирается явно: CPU по умолчанию, `whisper_use_gpu=true` только после проверки конкретного backend/устройства. CPU-прогон прошёл. Отмена ASR передаётся в штатный native abort callback; отменённый TTS прекращает работу между фрагментами.

Дополнительно исправлены: превышение лимита 45 с из-за округления VAD; склейка аудио после переполнения очереди; перенос захваченных кадров в новый сеанс; запоздалая отправка старого вопроса следующему студенту; отложенная очистка уже нового диалога; повторные обращения к заведомо исчерпанному Codex при включённом fallback. Временный rate limit отличается от исчерпанной квоты. Неразобранная реплика вызывает локальную голосовую просьбу повторить, без LLM-запроса; отсутствие фактов само по себе не вызывает лишней просьбы уточнить. В C++ добавлены локальный allowlist provider-ов и StopCharacter, но их реальная компиляция/очистка буферов остаётся целевой проверкой.

Отмена HTTP-загрузки базы больше не снимает обслуживание, пока нативный поток ещё строит индекс. Завершение атомарного импорта дожидается фактически, затем актуализируется готовность и только после этого разрешаются новые разговоры; сценарий проверен отдельным тестом.
