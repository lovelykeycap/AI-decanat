# Локальный протокол desktop ↔ backend, v1

Привязка: `127.0.0.1`, HTTP и WebSocket. Launcher передаёт desktop путь к приватному JSON-файлу через `DECANAT_CONNECTION_FILE`. Его поля — `url` и случайный `token`; в query string токен не передаётся. Конфигурация с удалённым host не принимается desktop.

## Диалог

WebSocket `/v1/conversation`, заголовок `Authorization: Bearer <token>`. Разрешён один renderer-клиент на процесс. На подключении приходит снимок состояния; при разрыве сессия завершается и контекст очищается.

Команды — JSON. После начала обязательно передавать `session_id`, полученный из события; для сообщений воспроизведения — также `turn_id`.

| `type` | Назначение и дополнительные поля |
| --- | --- |
| `start` | Начало разговора; session_id ещё не нужен |
| `avatar_ready` | Подтверждение завершения вставания/посадки, не готовности ответа |
| `finish` | Немедленное завершение сессии |
| `sources` | Показ текущих источников, считается активностью |
| `activity` | Действие пользователя, сбрасывающее таймер ожидания |
| `text` | Текстовая диагностика, поле `text`; не кнопка/поле студенческого UI |
| `speech_start` | Сигнал начала перебивания от внешнего аудиоклиента |
| `audio_end` | PCM16 little-endian mono в `audio_b64`, частота в `sample_rate`; до 45 секунд |
| `playback_progress` | `played_characters`, подтверждённый префикс завершённых речевых фрагментов |
| `playback_finished` | Подтверждение фактического окончания звука |

В основной локальной конфигурации захватом/воспроизведением управляет AudioDeviceAgent внутри backend, поэтому renderer не должен воспроизводить PCM или дублировать playback-progress. Сообщения аудиоклиента оставлены для независимых проверок/адаптеров, не для ввода студента с клавиатуры.

Событие имеет поля `sequence`, `kind`, `session_id`, `turn_id`, `payload`:

- `snapshot`: актуальные state/history/answer/sources; активная история относится только к одному студенту.
- `state`: `idle`, `standing_up`, `listening`, `transcribing`, `thinking`, `speaking`, `sitting_down`.
- `avatar`: `action=stand|sit`; после реальной анимации renderer отвечает `avatar_ready`.
- `transcript`: распознанный вопрос в `text`.
- `turn_started`: начата обработка новой аудиореплики; убрать прежний текст и источники, не стирая каноническую историю текущего разговора.
- `answer`: структурированный ответ, подтверждающие фрагменты и имя фактически использованного провайдера.
- `speech`: PCM16 mono base64, sample_rate=48000, text, duration и `speech_marks` (`sample`, `characters`); renderer использует PCM для мимики. Аудиокомпонент подтверждает границы завершённых фрагментов после запланированного DAC-времени, а не пропорционально длительности. Незавершённый фрагмент при перебивании не считается подтверждённым целиком.
- `playback_stop`: немедленно сбросить звук и очереди мимики; ожидание остановки inference не задерживает эту команду.
- `sources`: исходные подтверждающие фрагменты, их название, происхождение и locator; внешние URL не открываются в системном браузере.
- `idle_warning`: `visible` и при показе `seconds`.
- `cleared`: очистить текст/источники студенческой сессии, `reason` — причина завершения.
- `error`, `command_error`, `clarify`: понятные русские сообщения; raw stderr, ключи и трассировки не отправляются студенту.
- `maintenance`, `knowledge_updated`: состояние обновления базы в даунтайме.
- `resync_required`: клиент отстал; соединение закрывается вместо бесконечного накопления событий.

Клиент не должен возобновлять старую реплику по задержанному callback. Окончание playback с другим turn_id игнорируется. Статусы генератора и JSON Schema находятся в `schemas/answer.schema.json`.

## Служебный доступ

Каждому служебному запросу нужен IPC bearer. Помимо него `/v1/admin/*`, кроме login, требует `X-Admin-Token`. Начальная настройка пароля выполняется оператором через CLI. Студенческий экран не содержит формы регистрации, конфигурации сервиса или редактирования вопроса.

`/v1/health` сообщает установленные компоненты, `knowledge_ready`/`knowledge_error`, фактическую готовность аудиоустройства и `restart_required`. Поиск прогревается при запуске; ошибка модели/несовместимый индекс блокирует start. После изменения устройств/речевых моделей настройки сохранены для следующего запуска, а новые разговоры блокируются до перезапуска. Смена провайдера сама по себе этого не требует. Успешный HTTP 200 не утверждает, что персонаж/мимика прошли визуальную приёмку.

`GET /v1/admin/diagnostics` возвращает health, версии среды, найден ли Codex, настроен ли API-ключ (только bool), метаданные базы и список PortAudio-устройств. Запись микрофона и проигрывание при перечислении не запускаются. Значение `audio.devices[].selection` можно сохранить в input_device/output_device; пустое поле выбирает системное устройство. Доступ к этому маршруту требует парольного входа сотрудника.

Отмена клиентом HTTP-импорта после начала построения индекса не возвращает систему из обслуживания, пока поток изменения базы не завершён. Это сохраняет запрет на обновление фактов во время разговора даже при оборванном служебном запросе.
