# Вымышленный контрольный корпус

Все кабинеты, даты, правила и имена в этом каталоге придуманы для разработки. Это не база для консультации студентов.

`knowledge/` следует основному контракту ZIP/JSONL. В нём 11 документов, 12 фрагментов. `cases.json` содержит 13 вопросов: перефразировка, контекст, исключения, точные дата/время/аудитория, конфликт двух источников, неизвестный факт, неясный вопрос, персональный статус и недоверенные инструкции в вопросе/документе.

Из корня проекта, при остановленном приложении:

```sh
.venv/bin/python tools/evaluate_answers.py --output .runtime/evaluation/retrieval.json
.venv/bin/python tools/evaluate_answers.py --provider codex --output .runtime/evaluation/codex.json
```

Без `--provider` сетевые запросы генерации не выполняются. `--provider codex` использует подписочный CLI, `--provider api` — настроенный API; fallback в проверке принудительно выключен в памяти. Конфигурация приложения не перезаписывается. `--case ID` ограничивает набор; `--lexical-only` явно выбирает диагностический FTS5-режим.

Отдельный индекс создаётся в `.runtime/evaluation`, рабочая база не заменяется. SHA-256 корпуса и сценариев, найденные ID, ответы, статусы, ошибки и времена сохраняются в отчёте. При известном исчерпании лимита/отсутствии авторизации оставшиеся запросы не отправляются.

PASS означает, что в top-8 присутствуют заданные источники, статус совпал, обязательные текстовые шаблоны найдены, запрещённые отсутствуют. Regex-проверка не доказывает смысловую корректность всех утверждений. Нужны просмотр полных ответов и отдельный расширенный набор на утверждённой вузом базе; этот маленький корпус не используется для заявления общего качества RAG.
