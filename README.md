# ИИ-аватар деканата

Проект информационного помощника: локальные речь и аватар, ответы по подготовленной базе через Codex либо API. Требования: [продуктовые решения](product-decisions.md), порядок работ: [план](development-plan.md).

**Текущее состояние:** backend уже запускается; ветка Codex проверена реальными запросами на явно вымышленных данных. Это ещё не готовая поставка аватара: Unreal/MetaHuman/ACE-ассеты и полная Windows/NVIDIA-сборка не проверены. Состояние компонентов и оставшиеся зависимости — [в журнале разработки](docs/progress.md).

## Окружение разработчика

Python 3.12; зависимости закреплены в `uv.lock`. Из корня проекта:

```sh
uv sync --python 3.12 --extra speech --extra models
uv run pytest -q
uv run ruff check backend tests tools
```

На текущем MacBook изолированный uv находится в `.tools/uv/bin/uv`, Python — в `.tools/python`, окружение — в `.venv`. Поэтому можно запускать без глобальной установки uv:

```sh
.venv/bin/python -m pytest -q
.venv/bin/decanat doctor
```

Для повторного sync в этом окружении:

```sh
UV_PYTHON_INSTALL_DIR="$PWD/.tools/python" UV_CACHE_DIR="$PWD/.cache/uv" .tools/uv/bin/uv sync --python 3.12 --extra speech --extra models
```

## Проверить backend с Codex

```sh
decanat init
decanat kb pack examples/knowledge .runtime/sample-kb.zip
decanat kb import .runtime/sample-kb.zip
decanat chat
```

В активированном окружении `.venv` команда `decanat` доступна напрямую; альтернативно используйте `.venv/bin/python -m decanat.cli`. `init` выполняется один раз. На текущем стенде начальный пароль создан и находится в `.runtime/initial-password.txt` (файл не входит в Git); после первого входа его нужно удалить. Пароль не выводится в отчёты и не используется как пароль по умолчанию на других установках.

Текстовый `chat` — средство проверки реального поиска/генерации/контекста, а не студенческий интерфейс и не замена обязательному голосовому аватару. `/exit` завершает его. Пример последовательности: «Как получить справку об обучении?» → «А сколько её делают?».

Пример базы **вымышленный**. Кабинет и сроки в нём не относятся к реальному вузу. Подготовка рабочей базы — по [контракту](docs/knowledge-base-contract.md); готовые JSON Schema находятся в `schemas/`.

## Локальный сервер и доступ сотрудника

```sh
decanat serve
```

Сервер слушает только `127.0.0.1:8765`. Параметры подключения для desktop записываются в `.runtime/desktop-connection.json` с приватными правами файла; это секрет текущего запуска, не ссылка для студента. Токен меняется при перезапуске. В студенческом режиме браузер и ОС не используются.

- Каждому HTTP/WebSocket-подключению нужен `Authorization: Bearer <IPC token>`.
- Вход сотрудника: `POST /v1/admin/login` с `{"password":"…"}`. Возвращённый токен передаётся в `X-Admin-Token`, действует 30 минут.
- Журнал, настройки, ключ и база доступны только после входа. Исходное аудио не архивируется.
- Обновление: `POST /v1/admin/knowledge` с бинарным ZIP. Во время разговора возвращается 409. Испорченный пакет не меняет действующую базу.
- `PUT /v1/admin/settings` принимает полный объект настроек, полученный через GET. Некоторые изменения требуют перезапуска аудиоустройств.
- `GET /v1/admin/diagnostics` показывает компоненты и аудиоустройства без записи микрофона и без раскрытия ключей. После изменения аудиоконфигурации новый разговор блокируется до перезапуска; переключение провайдера перезапуска не требует.
- `POST /v1/admin/api-key` сохраняет ключ в системном keyring. Незащищённого запасного файла для ключа нет.

Сервер и офлайн-команды изменения конфигурации используют общий процессный lock. Для `configure`, импорта через CLI и настройки моделей сначала остановите приложение. Веб-интерфейс Swagger намеренно не публикуется.

## Настроить API-ветку

В даунтайме:

```sh
decanat api-key
decanat configure api_model '"ИМЯ_ДОСТУПНОЙ_ВАМ_МОДЕЛИ"'
decanat configure provider '"api"'
```

Имя модели не подставляется наугад. Для основной ветки верните `provider` в `"codex"`. Автоматический переход на API включается отдельно (`api_fallback=true`), по умолчанию он выключен. Ключ также можно передать процессу через `OPENAI_API_KEY`, но он никогда не передаётся дочернему процессу подписочного Codex.

Codex вызывается без shell, в отдельном временном каталоге, с `--ignore-user-config`, `--ephemeral`, read-only sandbox, отключёнными shell/apps/plugins/web/компьютерными инструментами и JSON Schema. Это технические ограничения, а не подтверждение допустимости использования личной подписки для публичной эксплуатации. Проверка условий сценария остаётся отдельной задачей.

## Установить локальную речь

```sh
python tools/build_audio.py
python tools/install_models.py --speech --whisper-size small --configure
```

Первый скрипт собирает WebRTC Audio Processing и C ABI-мост в `.tools/native`, исходники скачиваются с фиксированными контрольными суммами. Второй скачивает Whisper, Silero VAD и Silero TTS в `models/`: ожидаемые SHA-256 и ревизии закреплены в `tools/model-sources.json`, файлы сверяются до подключения. Локальный результат записывается в `models/installed.json`. Файлы больших моделей в Git не входят. Модель TTS — исполняемый torch-пакет доверенного издателя, не произвольный файл из базы знаний.

До использования/распространения выбранных весов проверить их собственные условия; лицензия части исходников не распространяется автоматически на все checkpoints. Сейчас тестируется локальный русский Silero v5. Во время студенческого разговора модели не скачиваются.

На macOS после сборки:

```sh
decanat configure apm_library_path '"/АБСОЛЮТНЫЙ/ПУТЬ/К/ПРОЕКТУ/.tools/native/lib/libdecanat_audio.dylib"'
decanat configure speech_enabled true
```

Для Windows укажите путь к собранной DLL. Разрешение доступа к микрофону выдаётся приложению средствами ОС. Для работы с голосом нужны реальные input/output-устройства; неудачная инициализация отображается диагностикой, а не заменяется фиктивной озвучкой.

`decanat devices` перечисляет названия без записи звука; поле `selection` подходит для input_device/output_device. В текущей среде запуска список пуст, поэтому `speech_enabled` оставлен выключенным. Наличие моделей не подменяет доступ к устройствам.

Backend воспроизводит звук один раз через duplex-аудиопоток и передаёт его в AEC как опорный сигнал. Он же сегментирует реплики Silero VAD и передаёт их Whisper. Unreal получает PCM для мимики; собственный слышимый звук ACE должен быть отключён, чтобы избежать двойного голоса. Физическое перебивание и синхронизация мимики требуют отдельной приёмки на целевом компьютере.

Whisper по умолчанию использует CPU (`whisper_use_gpu=false`). GPU включается явно после проверки нужного backend и драйвера; в текущем ограниченном macOS-запуске автоматический Metal-режим приводил к нативному сбою выделения памяти. CPU-режим проверен. TTS формирует фрагменты с отметками завершения; при перебивании в контекст передаётся консервативно подтверждённый префикс, без предположения о том, какие слова успели прозвучать внутри оборванного фрагмента.

## Семантический поиск

```sh
python tools/install_models.py --embedding --configure
decanat kb import .runtime/sample-kb.zip
```

Результат — hybrid FTS5 + BGE-M3. Включение другой embedding-модели требует перестроить индекс в даунтайме. До установки модели доступен настоящий полнотекстовый поиск; это диагностическая конфигурация, не подтверждение итогового качества RAG. Векторный сервер, облачные embeddings и универсальный парсер документов не требуются.

## Desktop-аватар

Исходники desktop находятся в `desktop/Decanat`. Порядок получения и подключения настоящих ассетов описан в [инструкции Unreal](docs/unreal-setup.md). Подставных `.uasset` и мультяшного персонажа вместо согласованного образа нет.

Кандидат совместимого комплекта и аппаратный бюджет для первого стенда описаны в [целевой среде](docs/target-environment.md), статусы отсутствующих пакетов — в `assets/manifest/desktop-stack.json`.

После сборки приложения:

```sh
python tools/launch.py /путь/к/Decanat.exe
```

Launcher поднимает backend, ждёт его готовности и запускает desktop с приватным файлом подключения. При остановке backend закрывает desktop, чтобы не оставлять зависшую студенческую сессию. Для эксплуатации нужен отдельный киоск-профиль Windows; один fullscreen не блокирует системные сочетания клавиш.

## Проверки

Тесты проверяют вредоносные/повреждённые пакеты, неизменность базы после ошибки, точные источники, контекст, отмену и поздние результаты, лимиты/fallback, таймер, права сотрудника, журнал и нативный AEC. API проверяется настоящим SDK с контролируемым HTTP-транспортом; это не реальная оплаченная API-проверка. Реальные Codex-запросы не запускаются при обычном `pytest`.

Контрольный вымышленный корпус и правила оценивания — [examples/evaluation](examples/evaluation/README.md). Только при явно заданном `--provider` выполняются запросы к генератору:

```sh
python tools/evaluate_answers.py --output .runtime/evaluation/retrieval.json
python tools/evaluate_answers.py --provider codex --output .runtime/evaluation/codex.json
python tools/smoke_speech.py
python tools/smoke_echo.py
python tools/smoke_voice_pipeline.py
```

Последний скрипт использует выбранного реального провайдера и две синтетические реплики с контекстом, но не открывает микрофон/динамики и не запускает Unreal. Результат и специально подготовленные образцы ответов сохраняются в `.runtime/voice-pipeline-smoke.json` и `.runtime/voice-check-answer-*.wav`. Это проверка реальной inference-цепочки, а не всей поставки аватара. Все изменяющие индекс диагностические инструменты запускаются при остановленном приложении.
